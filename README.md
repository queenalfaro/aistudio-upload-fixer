# AI Studio Upload Fixer

Браузерное расширение (Manifest V3 под Firefox), устраняющее отказ Google AI Studio принимать файлы нестандартных форматов (`Dockerfile`, `.env`, `.zig`, `.rs`, `.py` и др.) путем их прозрачного перехвата в оперативной памяти JavaScript-рантайма и адаптивного преобразования в текстовые контейнеры.

Версия 4.0 работает на 100% в памяти (`MAIN` world): без использования `MutationObserver`, без кликов по кнопкам интерфейса и без повторных сетевых загрузок.

---

## Возможности

- **Перехват в памяти рантайма (Zero-DOM-Observer):** Ошибки валидации фронтенда и токенизатора бэкенда перехватываются на уровне сигналов Angular (`store.F.set`) до попадания в DOM. Интерфейс не отображает красных бейджей с ошибками.
- **Синхронная очистка стейта (Zero-Clicker):** Удаление отклоненных чанков выполняется нативным методом хранилища `store.ix(chunkId)`. Синтетические клики по кнопкам удаления и поиск селекторов в DOM не используются.
- **Сессионное обучение (Zero-Double-Upload):** Расширение не содержит жестко зашитых списков расширений. Файлы отдаются сервису как есть. Если тип отклонен бэкендом, расширение запоминает его в сессионном реестре и при последующих добавлениях подменяет на входе, исключая повторные запросы по сети.
- **Подавление системных тостов:** Сообщения об ошибках неподдерживаемых форматов перехватываются и подавляются на уровне прототипа контроллера `oG.prototype.Se`.
- **Сохранение контекста для LLM:** Файлы оборачиваются добавлением суффикса `.txt` к полному имени (`Dockerfile` → `Dockerfile.txt`, `main.zig` → `main.zig.txt`), сохраняя исходное имя и расширение для модели.

## Установка

### Временная установка в Firefox (Developer / Unpacked)

1. Откройте вкладку `about:debugging#/runtime/this-firefox` в Firefox.
2. Нажмите кнопку **Загрузить временное дополнение...** (Load Temporary Add-on).
3. Выберите файл `manifest.json` в корне репозитория.
4. Откройте или обновите страницу [Google AI Studio](https://aistudio.google.com/prompts/new_chat).

## Архитектура работы

```
[ Сброс / Выбор файлов ]
           │
           ▼
[ onDrop / onInputChange ] ────► Тип в сессионном кэше? ──► ДА ──► Подмена на .txt на входе
           │                                                 │
           │ (as-is)                                         └──► НЕТ ──► Передача как есть
           ▼
[ oG.prototype.Ipb ]
           │
           ├──► Валидатор фронтенда (TBb) ──► Отказ? ──► Подавление Se() + Auto-Heal в .txt
           ▼
[ FileService.readFile ] ──► Кэширование File в памяти
           │
           ▼
[ Backend Tokenizer RPC ]
           │
           ├──► Успех (READY) ──► Штатный подсчет токенов
           │
           └──► Ошибка ("Unsupported file")
                       │
                       ▼
           [ store.F.set Interceptor ]
                       ├── 1. Удаление chunkId из словаря до вызова origSet (DOM не видит ошибку)
                       ├── 2. Очистка стейта через store.ix(chunkId)
                       ├── 3. Регистрация типа в knownUnsupportedTypes (сессионное обучение)
                       └── 4. Диспатч исправленного new File([orig], `${name}.txt`)
```

## Таблица обработки форматов

| Формат / Тип файлов | Поведение при первой передаче | Поведение при повторной передаче в сессии |
|---|---|---|
| Нативно поддерживаемые (`.md`, `.js`, `.py`, `.json`, `.pdf`) | Передаются как есть, подсчитываются моделью штатно | Передаются как есть |
| Без расширения (`Dockerfile`, `Makefile`, `Procfile`) | Передаются как есть → перехватываются в `store.F.set` → конвертируются в `${name}.txt` | Конвертируются в `${name}.txt` на входе (без ошибки бэкенда) |
| Dotfiles (`.env`, `.gitignore`, `.dockerignore`) | Передаются как есть → перехватываются в `store.F.set` → конвертируются в `${name}.txt` | Конвертируются в `${name}.txt` на входе (без ошибки бэкенда) |
| Неподдерживаемые расширения (`.zig`, `.sol`, `.rs`, `.tf`) | Передаются как есть → перехватываются в `store.F.set` → конвертируются в `${name}.txt` | Конвертируются в `${name}.txt` на входе (без ошибки бэкенда) |

## Верификация и тестирование

Репозиторий включает автономный сквозной тест через протокол WebDriver BiDi (`ws://127.0.0.1:9222/session`), проверяющий рантайм на живом экземпляре Firefox:

```bash
python test_live.py
```

Сценарий теста:
1. Выполняет установку расширения через нативный метод BiDi `webExtension.install`.
2. Перезагружает вкладку `https://aistudio.google.com/prompts/new_chat`.
3. Передает пакет файлов: `README.md`, `test.js`, `Dockerfile`.
4. Проверяет, что `README.md` и `test.js` приняты как есть с подсчетом токенов.
5. Проверяет, что `Dockerfile` перехвачен в памяти без появления статуса ошибки в DOM и преобразован в `Dockerfile.txt`.
6. Передает второй `Dockerfile` и подтверждает срабатывание сессионного обучения на входе без повторной ошибки токенизатора.
7. Проверяет отсутствие классов `.token-status-error` и наличие валидных токенов у всех чипов.

## Безопасность и приватность

- **100% локальное исполнение:** Расширение не содержит внешних зависимостей, аналитики и телеметрии.
- **Безопасность данных:** Исходное содержимое файлов передается исключительно в API Google AI Studio напрямую из локальной памяти браузера. Расширение не пересылает данные на сторонние серверы.
